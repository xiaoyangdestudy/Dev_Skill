# 测试用例生成（本 Skill 内置）

本流程直接包含等价类划分、边界值分析、按测试点（POINT）分批设计以及格式校验能力。不得要求用户安装或调用独立的 `testcase-generator` Skill；它被卸载后，本 Skill 仍须可完成测试设计与校验。

## 输入与唯一项目产物

根据项目导航按需读取：

- `需求剖析/README.md`
- `01_需求梳理与范围边界.md`
- `02_H5与接口审查及待确认项.md`
- `03_技术设计与实施计划.md`
- 与目标 POINT 相关的原始设计、接口样例和已确认答复

测试用例统一写入项目约定的 `需求剖析/04_测试用例.md`，不强制再创建另一套 `test-case/` 目录或多个重复汇总文件。文档按 ITEM 分组，在每个 ITEM 下列出 POINT；每个 POINT 一次设计和校验，避免一次性展开无关场景。对于大型项目，仍可分批编辑同一文件。

## 生成方法

对每个 POINT：

1. 明确测试目标、前置条件、输入项、业务约束、风险和来源。
2. 仅依据确认过的需求/契约写预期。材料没有说明时，将场景放入“待确认预期/阻塞用例”，不能编造错误提示、状态变化或响应字段。
3. 对有约束的输入做等价类划分：有效类、无效类（空、格式不符、越权、缺失等仅在适用且有契约依据时）；每个用例尽量只改变一个等价类，其余条件保持有效。
4. 对范围/长度/数量/时间等边界使用边界值分析。典型取值为 min-1、min、min+1、有效区间内点、max-1、max、max+1；只生成业务实际存在的边界，不虚构限制。
5. 按业务风险和测试价值选择代表性组合，不追求机械穷举或固定用例数量。覆盖核心正向、关键异常、边界、多端链路和旧功能回归。
6. 跨端功能分别检查 H5→Bridge→App、App→后端、H5→后端的适用链路；不假设每条链路都存在。
7. 用例数据具体且可执行。涉及真实账号、Token、手机号等敏感信息时使用安全的测试数据约定，不写真实凭据。

## 文档分组建议

```md
# 测试用例

## 测试范围与依据

## ITEM-01：业务功能
### POINT-01：进入/初始化
<该 POINT 的用例>
### POINT-02：状态变化
<该 POINT 的用例>

## ITEM-02：接口与跨端联调
### POINT-01：参数与响应
<该 POINT 的用例>

## ITEM-03：回归与兼容
...

## 待确认预期/阻塞用例
...

## 覆盖摘要
- 已覆盖的 ITEM/POINT：
- 因契约缺失暂不能确定预期的 POINT：
- 未覆盖原因：
```

ITEM/POINT 编号使用稳定、可引用的短编号。需求变化时保留编号或注明变更映射，避免验收记录失去引用。

## 单条用例格式（文本协议 v0.2）

```md
## [P1] 验证活动进行中用户成功进入播放页
[测试类型] 功能
[前置条件] 活动状态为进行中；用户已登录；后端首部微剧数据符合已确认契约
[测试步骤] 1. 在活动 H5 点击“立即参与”。2. 观察 Bridge 参数并等待 App 打开播放页
[预期结果] 1. H5 按已确认契约调用 Bridge。2. App 收到约定参数并按已确认行为打开播放页
```

规则：

- 标题优先以“验证”开头，并包含 `[P1]` 到 `[P5]`；反向场景可标 `[反向]`。
- `[测试类型]`、`[前置条件]`、`[测试步骤]`、`[预期结果]` 为必需字段；字段间不插空行。
- 可用测试类型以脚本 `scripts/parse_text_protocol.py` 中的 `VALID_TEST_TYPES` 为准（如功能、兼容性、性能、稳定性、安全性等）。使用中文全角括号的类型必须与枚举精确一致。
- 步骤和预期结果都使用从 1 开始的连续编号；二者条数相同且逐项对应。步骤用中文句号分隔，步骤内部必要时可用顿号或分号。
- 不用 `{username}` 等占位符；预期写成可观测结果，避免“正常”“成功”“提示错误”等模糊句，除非后面明确说明可观察状态。
- 测试等级：P1 核心正向；P2 基本正向；P3 关键异常；P4 边界；P5 低频风险。
- 数量按输入项数量、规则复杂度、风险和覆盖要求决定，不设硬性配额。

## 校验脚本

Skill 自带脚本位于本 Skill 目录的 `scripts/`，只依赖 Python 标准库。验证目标文件：

```powershell
python <本Skill目录>/scripts/validate_test_cases.py "<项目目录>/需求剖析/04_测试用例.md" --check-duplicates
```

由调用环境替换 `<本Skill目录>` 和 `<项目目录>` 为实际绝对路径。也可不带 `--check-duplicates` 仅验证文本协议格式。目录校验会按脚本支持的 ITEM/POINT 文件布局扫描；本工作流默认直接对单一 04 文档校验。

校验后处理所有格式错误；重复检测是提示，不要盲目删除语义不同的用例。运行结果写入 06 验收记录时，注明真实脚本路径、命令和输出摘要。脚本不是业务正确性的证明，仍需检查来源、覆盖和预期可验证性。

可选导出 Excel 时使用 `scripts/export_test_cases_to_excel.py`；仅在用户需要 Excel 时运行，且遵从脚本依赖提示。默认不增加 Excel 产物。
